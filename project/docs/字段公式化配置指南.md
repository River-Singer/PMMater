# 字段公式化配置指南

成员主要维护负责人、计划、实际进展和处理依据。日期差、到期提示、资料缺口及容量余量可以由飞书 Fx 随事实更新。本指南依据当前字段字典整理，先设置延期相关公式，再按需要增加其他列。执行状态的公式见 [状态自动显示与维护](状态自动显示与维护.md)。

## 适合公式化的字段

| 字段或结果 | 可以怎样设置 | 配置依赖 |
|---|---|---|
| 延期判断基准日、基准来源 | 原计划完成优先，缺失时使用当前预计完成并显示来源 | 本行日期 |
| 延期状态、是否延期 | 自动区分已延期未完成、延期完成、风险及待核对 | 有效执行任务、基准、状态及实际完成 |
| 实际延期天数、预计延期天数 | 按自然日分别计算已发生延期和预测偏差 | 基准、当前日期、实际或预测完成日期 |
| 预计工期、实际工期 | 起止日期相减加 1，包含首尾 | 起止齐全且顺序正确，预计工期使用当前预测并逐项回退到原计划 |
| 距承诺完成天数 | 未关闭任务的基准日减今天，0 表示今天到期 | 完成基准及任务状态 |
| 开始情况核对 | 开始计划已到且实际开始空时显示需确认 | 当前预计开始、实际开始及适用状态 |
| 计划资料缺项 | 拼接缺负责人、计划起止、工作说明、完成标准、验收人等提示 | 条件必填规则及字段类型 |
| 补救落实状态 | 自动提示缺时间、今天核对、已到期、待补验证结果 | 已登记措施及补救事实 |
| 下一步检查点 | 最迟时间已过时提示核对结果 | 带时区的下一步最迟时间 |
| 进展更新提示 | 根据进展确认时间和项目更新间隔提示核对 | 当前负责人、本次进展来源和已配置间隔 |
| 人员周余量、容量状态 | 净可用减项目、运维和缓冲，区分超配与缓冲冲突 | 完整且已确认的周容量 |
| 父级完成率、Todo 完成率 | 对真实执行叶子去重后汇总 | 明确的叶子关联及完成事实 |
| 风险数量、交付物验收摘要 | 对已关联记录按状态筛选后计数或汇总 | 双向关联、查找引用及过滤条件 |
| 建议优先级 | 按已有影响×紧迫性矩阵显示建议 | 人工确认优先级，P0 的理由仍需提供 |
| 项目 WK、本周成果到期 | 按项目起始周及承诺时间计算展示 | 项目关联、周一至周日口径、具名成果确认 |

其中“是否延期”等已经是本包的只读计算结果。离线 Excel 中的派生值在重新导出时刷新。飞书可增加下文的独立公式列，现场核对输出类型后再纳入视图和统计。字段定义见 [字段字典](字段字典.md)。

## 输入与设置顺序

以下可复制公式要求输入为真实的仅日期值，项目时区按本项目配置核对，示例为 `Asia/Shanghai`。先检查源值中的时分秒及显示格式。保留时间的副本需要定制日期辅助列，下面提供一种归一化写法。

```text
IF(ISBLANK([实际完成]),"",DATE(YEAR([实际完成]),MONTH([实际完成]),DAY([实际完成])))
```

定制时，判空仍检查原始输入字段，仅在原始值非空后，将比较或相减的引用改为归一化日期。日期辅助列的 `""` 分支按空文本处理。实际开始、原计划起止、当前预计起止及补救日期采用相同约定。下一步最迟时间、进展确认时间保留时分秒。

先核对实际副本的字段名称、单选文本、日期和关联类型，再在公式编辑器中选择字段。以下新列名是本次建议的配置名称。

| 设置顺序 | 新列 | 输出与用途 |
|---|---|---|
| 1 | 执行叶子（辅助） | 1 代表本次纳入执行计算，0 代表汇总或已转出行，空表示关系尚待核实 |
| 2 | 延期判断基准日（公式）、延期基准来源（公式） | 日期展示、来源文本 |
| 3 | 延期状态（公式） | 文本 |
| 4 | 是否延期（公式） | 文本，含待核对和不适用 |
| 5 | 实际延期天数（公式）、预计延期天数（公式） | 天数展示，未知分支显示空文本 |
| 可选 | 补救落实状态（公式）、人员周剩余小时（公式） | 分别设在任务表和人员周资源表 |

数值示例用 `""` 显示未知。该分支返回空文本，数值统计前需要按可计算状态筛选，并在目标副本验收公式结果格式、导出/API 类型和统计行为。已核对事实后得到的 0 仍是有效结果。

### 执行叶子辅助列

WBS 中先核对「父级WBS」的反向关联，新增或选用列出真实直接子记录的字段，例如「直接子项（关联）」。再使用查找引用的计数方式得到「直接子项数（辅助）」。配置及样例验证完成后，空子项集合的计数应为 0。关系未接入、读取不完整或计数缺失时保留待核实。

下式用于新建 WBS 的「执行叶子（辅助）」。它同时检查「层级类型」和真实子项数，因此带子任务的任务行也归入汇总范围。

```text
IF(OR(ISBLANK([层级类型]),ISBLANK([直接子项数（辅助）])),"",
  IF(AND([层级类型]="任务",[直接子项数（辅助）]=0),1,0))
```

计算范围应限于本项目有效记录，并由接入配置排除历史迁移别名。字典里的「子节点数」「任务数量辅助字段」可用于已保存快照核对，原生公式需要经过验证的实时关系。

运维表使用同名辅助列时，改用下面的公式。它依据「已转入项目任务」排除已转入 WBS 的旧事项。

```text
IF(ISBLANK([已转入项目任务]),1,0)
```

WBS 和运维共享「原计划完成」「当前预计完成」「实际完成」「延期风险标记」及补救字段名称，可以复用后文公式。运维没有 WBS 的层级字段。项目概览表使用「基线开始」「基线完成」，配置项目级显示时需选择该表的实际名称。

## 延期公式

### 延期判断基准日（公式）

```text
IF(ISBLANK([原计划完成]),
  IF(ISBLANK([当前预计完成]),"",[当前预计完成]),
  [原计划完成])
```

### 延期基准来源（公式）

```text
IF(ISBLANK([原计划完成]),
  IF(ISBLANK([当前预计完成]),"缺完成基准","当前预计完成（未设原计划）"),
  "原计划完成")
```

原计划完成日保留已确认承诺。缺原计划时，当前预测作为临时基准，来源列会明确标出。该情况下修改预测会改变比较基准，需要由 PM 确认并维护受控原计划。日期修改的授权和历史核对沿用 [日期变更审议与留痕](日期变更审议与留痕.md)。

### 延期状态（公式）

```text
IF(OR(ISBLANK([执行叶子（辅助）]),[执行叶子（辅助）]=""),"范围待核实",
  IF([执行叶子（辅助）]=1,
    IF([状态]="取消","已取消",
      IF(AND(ISBLANK([原计划完成]),ISBLANK([当前预计完成])),"缺完成基准",
      IF(OR(
        IF([状态]="已确认完成",ISBLANK([实际完成]),FALSE),
        IF(ISBLANK([实际完成]),FALSE,[实际完成]>TODAY()),
        IF(OR(ISBLANK([实际开始]),ISBLANK([实际完成])),FALSE,[实际完成]<[实际开始]),
        IF(ISBLANK([实际完成]),FALSE,IF([状态]="已确认完成",FALSE,TRUE))
      ),"待核对",
        IF([状态]="已确认完成",
          IF([实际完成]>[延期判断基准日（公式）],"延期完成","按期完成"),
          IF(TODAY()>[延期判断基准日（公式）],"已延期未完成",
            IF(OR([状态]="受阻",[延期风险标记]="有延期风险",
              IF(ISBLANK([当前预计完成]),FALSE,[当前预计完成]>[延期判断基准日（公式）])
            ),"有延期风险","未见延期信号")))))),
    ""))
```

执行范围尚未核实时显示“范围待核实”，实际延期天数保持空。完成延期按「状态＝已确认完成」及有效实际完成日期计算。单独录入实际完成、完成日期在未来或实际起止倒置时，显示待核对。工作说明、负责人或完成依据缺失会进入每日资料核查，已具备的延期日期事实仍可计算。实际开始为空时，仅在存在其他矛盾条件时阻断延期计算。

到期日当天保持未逾期，跨过项目当地日期后才显示已延期未完成。任务已确认完成后，延期天数固定为实际完成与基准的差值。受阻、主动风险标记或预测晚于基准时，在到期前显示有延期风险。

### 是否延期（公式）

```text
IF([延期状态（公式）]="","",
  IF([延期状态（公式）]="已取消","不适用",
    IF(OR([延期状态（公式）]="已延期未完成",[延期状态（公式）]="延期完成"),"是",
      IF(OR([延期状态（公式）]="按期完成",[延期状态（公式）]="未见延期信号",[延期状态（公式）]="有延期风险"),"否","待核对"))))
```

该列按文本展示。统计时可筛选“是”，风险关注同时筛选「延期状态＝有延期风险」。接入映射保留原只读布尔 `is_delayed` 的类型约定，此文本展示列单独使用。

### 实际延期天数（公式）

```text
IF([延期状态（公式）]="已延期未完成",
  TODAY()-[延期判断基准日（公式）],
  IF([延期状态（公式）]="延期完成",
    [实际完成]-[延期判断基准日（公式）],
    IF(OR([延期状态（公式）]="按期完成",[延期状态（公式）]="未见延期信号",[延期状态（公式）]="有延期风险"),0,"")))
```

单位为自然日。基准是 11 月 14 日，11 月 14 日尚未确认完成时为 0 天，11 月 15 日为 1 天。11 月 16 日确认实际于 11 月 15 日完成，结果保留为 1 天。

### 预计延期天数（公式）

```text
IF([执行叶子（辅助）]=1,
  IF(OR([状态]="取消",[状态]="已确认完成"),"",
    IF(OR(ISBLANK([原计划完成]),ISBLANK([当前预计完成])),"",
      MAX(0,[当前预计完成]-[原计划完成]))),
  "")
```

这列比较当前预测与原计划，需两者齐全。若原计划 11 月 20 日、当前预测 11 月 23 日，预计延期为 3 天。当前日期尚未超过原计划时，实际延期仍为 0，延期状态显示有延期风险。已完成任务查看其实际延期天数。

## 补救与资源公式

### 补救落实状态（公式）

```text
IF([执行叶子（辅助）]=1,
  IF([状态]="取消","已取消",
    IF(ISBLANK([延期补救措施]),"",
      IF(ISBLANK([实际补救时间])=FALSE,
        IF([实际补救时间]>TODAY(),"待核对实际补救时间",
          IF(ISBLANK([补救验证结果]),"待补验证结果","已登记落实结果")),
        IF(ISBLANK([预期补救时间]),"待补预计时间",
          IF([预期补救时间]<TODAY(),"已到期，核对落实结果",
            IF([预期补救时间]=TODAY(),"今天核对落实","待落实")))))),
  "")
```

补救措施由负责人提供，落实日期及验证结果按真实发生情况维护。显示已登记落实结果后，agent 继续检查措施效果、尚存风险和需要的决定。措施责任人缺失、继续还是等待、恢复条件和下一检查点由每日情景巡检追问。日期到期仅产生核对提示。完整问法见 [每日字段情景与17点升级](每日字段情景与17点升级.md)。

### 人员周剩余小时（公式）

在「人员周资源安排」表新建该列。

```text
IF(OR(ISBLANK([确认时间]),ISBLANK([净可用小时]),ISBLANK([项目分配小时]),ISBLANK([运维分配小时]),ISBLANK([未分配缓冲小时])),"",
  [净可用小时]-[项目分配小时]-[运维分配小时]-[未分配缓冲小时])
```

输入 0 小时有效。负值表示当前分配占用了缓冲或超过容量，结合项目与运维之和判断。

| 已确认的数据 | 容量解释 |
|---|---|
| 项目分配＋运维分配大于净可用 | 超配，需要协调 |
| 两者未超过净可用，但扣缓冲后余量为负 | 缓冲冲突，需要核对分配 |
| 剩余小时大于或等于 0 | 按已登记分配计算仍有相应余量 |
| 输入未齐或未确认 | 待确认，保持空余量 |

净可用已包含登记时扣除的外部占用和休假。此处按净可用计算一次。员工已有容量和休假事实也参与评估，日常人力确认仍按成员类型排除员工。确认身份、确认时间有效性及变更依据由既有资源校验核对。每日工作安排表的列名和粒度不同，使用时应选择对应半日字段。

## 其他列的配置口径

| 结果 | 适用公式规则或前提 |
|---|---|
| 预计工期 | 当前预计起止各自缺失时回退至原计划。两端均有效且结束不早于开始时，工期＝结束－开始＋1 |
| 实际工期 | 两个真实实际日期齐全且有序时，工期＝实际完成－实际开始＋1 |
| 开始核对 | 当前预计开始已到、实际开始为空且任务未关闭时，显示“核对已开工漏填或尚未开工” |
| 计划资料缺项 | 按任务所处情景列缺项。实际开始、实际完成在事件未发生时保持可空 |
| 下一步检查点 | 对真实「下一步最迟时间」与 `NOW()` 比较，已过则提示核对结果。当前模型需通过进展及下一步事实确认是否已完成 |
| 进展更新 | 结合项目设定的更新间隔、当前负责人和进展确认时间判断。具体天数采用项目配置 |
| 本周成果 | 使用「本周成果承诺」表自身的承诺日期、状态和结果依据，保留确认及成果完成时间 |
| WK | 查找引用项目基线开始，按其所在周为 WK01、周一至周日计算。节假周仍保留周序号 |

工期包含首尾，延期天数取两个日期的差值。字段里的延期原因、补救方案、优先级理由、验收结论和资源到位事实由责任人提供，并通过既有证据流程核验。

## 父级进度与工作日计算

父级完成率需要先确定全部后代中的唯一执行叶子，取消项从有效分母排除，已确认完成的有效叶子进入分子。一个工作包完成 1/1，另一个完成 0/9，合并后为 1/10＝10%。真实反向关联、查找引用和去重后的叶子集合是配置前提。

两级 WBS 可以在已核验的层级范围设置叶子与上级的关联，再统计有效任务数和已完成数。存在父任务、Todo 或更多层级时，应由明确的后代叶子关联或 agent 维护的叶子—祖先关系提供输入。直接子项计数用于叶子识别，整棵树进度需独立汇总。

现有导出还有两处聚合边界待统一。字典中的「已完成子级数」包含取消项，当前计算只计已确认完成。旧父级汇总还可能将空分组计入分母。配置新 Fx 时使用本节的执行叶子及取消口径，现有导出结果在这两类样例上需复核。

自然日公式可以直接使用本指南。工作日工期和延期天数需要关联已经核验的项目日历，逐日采用中国大陆法定假期、调休工作日及公司例外。`NETWORKDAYS` 的默认周末规则需要补充实际日历才能覆盖调休。

## 配置验收

先在项目副本中逐项核对，再启用视图筛选或统计。以下以项目当地今天为 11 月 14 日示意。

| 样例 | 期望结果 |
|---|---|
| 基准 11/14，未完成且没有其他风险 | 未见延期信号，是否延期＝否，实际延期 0 天 |
| 基准 11/13，仍未完成 | 已延期未完成，实际延期 1 天 |
| 基准 11/20，当前预测 11/23 | 有延期风险，是否延期＝否，预计延期 3 天 |
| 已确认完成，基准 11/12，实际完成 11/13 | 延期完成，实际延期 1 天，后续日期变化时保持 1 天 |
| 已确认完成，实际完成为空 | 待核对，实际延期天数空 |
| 实际完成在未来，或存在实际起止倒置 | 待核对，实际延期天数空 |
| 实际开始未填，已确认完成日期有效且晚于基准 | 延期完成，同时保留实际开始资料核对 |
| 状态仍待确认，但已填实际完成 | 待核对，由 PM / agent 核实状态与日期 |
| 原计划和当前预计完成均空 | 缺完成基准，实际延期天数空 |
| 缺原计划，仅有当前预计完成 | 使用当前预计完成，来源显示未设原计划 |
| 取消或汇总行 | 取消显示不适用，汇总行的执行延期显示空 |
| 子项关系尚未核实，执行叶子辅助为空 | 范围待核实，是否延期＝待核对，实际延期天数空 |
| 补救日为今天 / 昨天且无实际记录 | 今天核对落实 / 已到期核对落实结果 |
| 容量 C=40、项目 P=24、运维 O=8、缓冲 B=4 | 剩余 4 小时 |
| 资源任一值空 / C=0 且其余均为 0 并已确认 | 空余量 / 0 小时 |
| 空分组、父任务、取消叶子或多级后代 | 验证执行范围、去重分母和完成分子 |

TODAY/NOW 依赖平台计算及目标副本的时区配置。官方给出 NOW 在服务端计算模式下编辑时每 5 分钟、非编辑时每 30 分钟更新的说明。TODAY 的精确刷新时刻和目标副本时区仍需跨午夜验收。正式 10 点、17 点提醒由宿主可信时钟触发。周五 HTML 和飞书文档按约定截止时点保存快照，保留当时的事实与计算结果。
