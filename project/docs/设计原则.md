# 设计原则与专业依据

本版适用于一套表管理一个项目，采用滚动细化：近期周承诺具体到可验证成果，月度看里程碑/范围/资源预测，阶段以交付证据和有权决定为依据。

- 项目交付和独立运维分别执行与统计；人员容量同时核对，任务数不等于工作量。
- 原批准基线、当前预测、真实实际和周承诺独立。历史快照不能用今天的数据补造。
- 风险、已发生问题、阻塞、延期和信息缺失分开；管理判断有来源和未知项。
- 成员提供事实，会议审议方案与取舍；AI 建议和妙记自动待办不等于已批准决定。
- 工作地点不等于投入，缺回复不等于缺勤；净可用容量包含项目及对应运维，已扣占用不重复计算。
- 日历先覆盖项目有效期，再逐年核齐官方放假/调休及公司例外；未知年份不自动提醒。
- 周五材料先保留审议版，再保留会后决定和回填结果；日程、邀请和成员接受分别核验。
- 同一事实支撑飞书文档与 HTML，注明截止和来源；不同执行宿主共享规则，不默认双向同步。
- 使用入口是智能体对话、Excel 与独立 HTML。智能体负责调取、校验和生成；HTML 作为可直接打开的快照，交互只在报告文件内完成，不承担数据编辑或本地服务职责。

方法参考：[PM²](https://pm2.europa.eu/pm2-methodologies/pm2-project-management_en)、[GovS 002](https://projectdelivery.gov.uk/library-products/government-functional-standard-govs-002-project-delivery/)、[APM 资源规划](https://www.apm.org.uk/resources/find-a-resource/competence-framework/overview/planning-managing-deployment/)、[Kanban Guide](https://kanbanguides.org/the-kanban-guide/2025.5/)。采用可裁剪原则，不声称提醒时刻、风险阈值或人员工作制由这些方法统一规定。

日期比较保留修改前后证据，不以推断代替编辑者/编辑时刻。原始承诺指提供证据中首次观察的承诺；轮询不保证捕捉两次读取之间改回原值的变化。日期异常只提出核对，不判断个人意图。真实复核可降低优先级但不擦除历史。
