# 日期变更审议与留痕

审计用于核对日期证据是否影响延期呈现。它不会根据一次修改推断个人动机，也不能阻止拥有底层管理权限的人修改数据库。

## 跟踪范围与材料

保留项目、项目任务、运维事项的基线/预测日期、实际开始/完成，以及已确认周成果的期限/完成时间。优先核对后移基线、提前实际日期、清空日期等使同一时点延期减少或消失的变更。普通预测调整、有效纠错和已核实重排仍留历史，降低提醒优先级。首次补录实际日期本身不等于异常；若与更晚的进展确认或观察到的未完成状态冲突，展示证据强弱，交 PM 核实。

材料显示记录编号、修改前后值、对照时点、完成/开始偏差自然日、来源、操作者标签、实际修改时点或观察区间、批准/事后复核记录及下一步。负责人不是修改者；本地 actor 是调用方标签，不是身份认证。仍对照首次观察到的承诺及首次填报实际日期，不把它们冒充立项以来的完整历史。

## 留痕来自哪里

- 本地 Store/Excel 导入使用事件日志的前后值、事件时间及操作者标签。
- 飞书直接编辑由宿主审计事件或持久观察捕捉。包内 observer 在同一运行台账中追加变化快照、事件差异与每次成功读取检查点；无变化只保存指向已有快照的检查点。
- 首次读取只建立比较起点，之前改过什么未知。观察时间不是实际编辑时间；操作者未知。两次读取之间改动又改回，轮询无法识别。历史覆盖不足不能被描述成“没有改期”。

原生飞书宿主也需实现等价持久留痕，不能仅靠模型聊天记忆。保留原台账并备份，不为一次失败换新文件；没有实现防篡改存证或管理员级保护。

```text
python -m pm_core.cli schedule-audit --db workspace/project.sqlite3 --out workspace/日期核对.json --html workspace/日期核对.html
python -m pm_core.cli schedule-audit --config workspace/feishu.json --ledger workspace/runtime.sqlite3 --out workspace/日期核对.json --html workspace/日期核对.html
python -m pm_core.cli agent-tick --config workspace/feishu.json --ledger workspace/runtime.sqlite3
```

飞书预览仍会把已读取事实追加到本地观察台账，不写业务表、不发通知；不提供 --ledger 的独立汇报只能标历史未知。实时飞书读取采用真实捕获时点，不能用 --now 倒签；历史报告应读取真正保存的快照。

## PM 私信与周五审议

优先/中等核对项只能进入配置的 PM 私信渠道：`pm_private_chat_id` 必须为核实的 PM 私聊，`pm_private_recipient_id` 必须等于项目 pm_id，PM 还须在 allowed_recipients 中。缺私信渠道时输出 pending_private_channel，不转发到项目群。按核验工作日、巡检窗口和 enabled 运行，事件身份持久防重；不会每次巡检重复发送同一旧变更。

周五 HTML 包含日期变更审议；会上核对真实完成证据、纠错原因和调整范围。会后创建新报告并关联会前版。已保存周报冻结当时审计结果，重试渲染不把后来历史或批准倒灌进去。

## 记录批准与事后复核

配置 schedule_audit.decision_makers 是有权确认名单。事前批准用 approved_changes，事后核对用 reviewed_changes；两者都要精确匹配目标表、记录与每个字段的修改前后值，并保存人员、时点和依据。仅引用旧 baseline_change_id 或在任务文字里写“已批准”不能消除新提醒。事件自带批准/复核还须来自 trusted_approval_sources；不要把普通任务文字源列为可信决定源。

下面是配置结构的虚构例子，必须替换为实际核实的决定。它表示事后确认纠错，不声称修改前已经获批：

```json
{
  "decision_makers": ["PER-PM"],
  "reviewed_changes": [{
    "table": "wbs", "record_id": "WI-EXAMPLE",
    "changes": {"baseline_finish": {"before": "2026-11-05", "after": "2026-11-13"}},
    "reviewed_by": "PER-PM", "reviewed_at": "2026-11-13T15:00:00+08:00",
    "kind": "correction", "evidence": "https://example.invalid/confirmed-review"
  }]
}
```

reviewed_at 须不早于实际编辑/发现时点，且不能晚于报告截止时间。有效事后复核降为信息留档并保留原提醒级别；approved_at 落在未知修改区间时不能证明事前批准，仍待核实。批准或复核不得抹去原日期。

本地 `management-review --config <excel配置>`、`schedule-audit --config <excel配置>` 使用该政策；生成周报时可用 `--audit-policy <仅包含上述审计政策的JSON>`，保存政策生效时的审议版。无政策时保持未核实状态。[虚构日期变更示例](../demo/日期变更审议.html)及其[观察来源](../demo/日期观测来源.json)独立于主示例库。
