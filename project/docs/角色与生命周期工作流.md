# 角色与生命周期工作流

成员更新本人任务与安排，PM 汇总并维护计划、风险及决定请求，PO/资源协调人解决人员与外部协作，验收人给出真实验收结果，业务决定人处理范围/基线及重要取舍。Agent 检查、催收、生成材料并按预设授权执行有依据的动作，不替成员编造事实。

人力资源确认仅面向类型已核实的非员工：每日安排、周容量、月度未来资源窗口及对应缺失催填均排除员工。身份未知先交 PM 核实。员工已有资源/休假数据继续用于协调，任务进度、延期与验收职责不变；“免资源确认”不能把历史未确认安排变成已确认。

| 阶段 | 必须核对 |
|---|---|
| 启动 | 单项目目标、边界、决定人、成员身份/参与窗口、项目日历、输出和执行授权 |
| 计划 | 交付物/WBS、独立运维入口、里程碑/依赖、角色和容量、验收条件 |
| 执行 | 周一计划、每日非员工安排、项目工作日10点任务就绪及资源影响巡检、周五审议、会议行动和变更 |
| 月度/阶段复核 | 关键交付预测、范围风险、未来资源窗口、阶段证据与待决定项 |
| 验收移交 | 成果版本、验收结论、运维接收人、遗留事项及交接条件 |
| 结项 | 真实结项决定、资源释放/退出、归档与原项目提醒关闭 |

阶段日期到达或任务比例达标不能替代批准。基线结束已到但仍执行时先暴露提醒/人员窗口缺口，不直接判退场。周/月/阶段共用事实，不要求成员重复填写相同材料。

完整操作节奏、工作日规则和人员容量方法见 [工作节奏与字段](../references/operating-method.md)。周五延期与补救材料在会前、会后分别保存，妙记的建议/决定分流后再回填。

10点巡检按 [任务与资源影响规则](每日任务巡检与资源影响.md) 检查最小子任务并逐级追溯。成员补本人事实；PM处理无人承接、不可联系及资料缺口；PO协调人力、接口和物资；决定人明确取舍。所有未落实资源进入延期风险材料，未关联任务先补定位，不把“资源未落实”直接改写成“项目必然延期”。

PM 在日常巡检私信中核对优先日期变更，在周五材料中审议前后日期、历史偏差及依据；普通成员提醒不公开归因。已核实纠错或重排留档、降低提醒级别，不能删原承诺或重写旧周报，详见 [日期变更审议](日期变更审议与留痕.md)。
