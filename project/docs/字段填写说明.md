# 字段填写说明

精确字段与枚举以 [字段字典](字段字典.md) 为准；模板由同一 catalogue 生成。成员使用自己的任务/安排入口，不必维护全部底层字段。

| 场景 | 必须维护的事实 |
|---|---|
| 建任务 | 目标、归属、责任、计划/预计日期、完成标准；未知项保留待分流 |
| 工作日10点任务巡检 | 补标题/工作说明/完成标准、当前计划起止、有效负责人及验收人；负责人登记有时点的本人进度反馈；无负责人交PM分配 |
| 未落实资源 | 在人员安排/休假、接口清单或提醒与风险中登记来源、责任人、预计/最晚落实时点、相关任务、影响、下一步；无任务关联保留待定位风险 |
| 周一计划 | 全体任务负责人填写本周成果/中间检查点、期限、验证方式、所需协作；非员工另确认本周容量 |
| 实际开始 | 已发生的实际开始日期；尚未开始的阻塞不虚填开始 |
| 进展变化 | 最新进展说明、预测、依据与下一步；业务确认时间不能由发提醒刷新 |
| 延期或预测推迟 | 区分实际原因与未来风险，说明影响、解决措施、行动责任/期限、需要的决定 |
| 提交/验收 | 真实成果和版本、提交依据、验收人/意见；任务完成与成果验收独立 |
| 周五总结 | 截至会前的实际结果、延期说明、补救进展、未解决部分和候选方案 |
| 非员工每日安排 | 半日地点、专职/兼项、可用于项目及对应运维的小时、分配份额、未来休假变化 |
| 未来休假 | 起止/半日、提出/确认/撤销状态、依据、交接人和影响 |
| 周资源 | 非员工确认净可用小时、项目/运维分配、未分配缓冲；未知不填零。员工不催确认，已有事实继续保留 |

延期说明与解决措施在两张执行表均可见，并进入周五 HTML；多条措施关联具名执行行动。补救落实后继续检查交付是否恢复，不能自动完成原任务。调整预测不覆盖基线或已确认周承诺。

每日、周度和月度的人力资源确认都按通讯录“类型”排除员工，不按“项目角色”判断；类型待确认时先核实身份。员工仍维护任务与验收，PM 可维护其真实资源和休假记录；免确认不等于容量已知或已确认，也不删除历史数据。新增每日确认只选择已知非员工，历史记录可单独更正。

全天安排拆成两个半日记录，全天 6 小时不能给 AM/PM 各填 6。地点、劳动关系和投入方式是独立字段。未来计划不写成已发生实际，未回复不算缺勤；可用总量含项目和对应运维，避免扣两次运维或休假。

条件填报与提醒详见 [工作节奏](../references/operating-method.md)；会后回填详见 [会议行动](../references/meeting-actions.md)。

资料完整才具备执行条件；资料不足的任务仍保留在总体待办。任务负责人有值不等于本人已承接，近期进展、进展确认时间及确认人为当前负责人只作为“已有本人反馈”依据。任务→上级→项目以及资源影响的完整填写与复盘口径见 [每日任务巡检与资源影响](每日任务巡检与资源影响.md)。

## 日期修改时补什么

计划/实际日期纠错或调整要保存原值、理由和证据。实际开始/完成是成员事实，不因补录一律要求批准；涉及基线或验收决定仍按授权执行。使延期减少的日期变化进入 [日期变更审议](日期变更审议与留痕.md)，PM 核对后登记精确字段的纠错/重排决定，不能只复用旧变更编号。
