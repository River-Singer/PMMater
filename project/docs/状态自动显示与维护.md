# 状态自动显示与维护

“待分流”是原有「状态」单选列中的一个选项，不是独立列。成员日常不必反复手选这个状态：建议新增只读的 **「执行状态（公式）」**，在成员视图用它展示当前执行事实，并隐藏旧「状态」。原状态暂由 PM / agent 根据有依据的取消、受阻、验收决定维护，保留兼容接口；本次没有删除原字段、选项或历史值，也没有修改真实飞书表。

## 可复制的 Fx

在 WBS 总表新建公式字段「执行状态（公式）」，使用下面的公式。输入是旧「状态」及事实字段，**输出列不引用自身**。以下名称对应本包字段字典；飞书副本的列名、单选选项、人员/关联和日期类型须先逐一匹配。在公式编辑器中重新选择实际字段，以编辑器解析成功为准。

```text
IF([状态]="取消","取消",
  IF([状态]="受阻","受阻",
    IF([状态]="已确认完成",
      IF(AND(ISBLANK([实际开始])=FALSE,ISBLANK([实际完成])=FALSE,ISBLANK([完成依据])=FALSE),
        IF([实际完成]>=[实际开始],"已确认完成","待核对"),
        "待核对"),
      IF(ISBLANK([实际完成])=FALSE,
        IF(ISBLANK([实际开始]),"待核对",
          IF([实际完成]>=[实际开始],"待确认","待核对")),
        IF(ISBLANK([实际开始])=FALSE,"进行中",
          IF(AND(ISBLANK([负责人])=FALSE,ISBLANK([当前预计开始])=FALSE,ISBLANK([当前预计完成])=FALSE),
            IF([当前预计完成]>=[当前预计开始],"待开始","待核对"),
            "资料待完善"))))))
```

| 情况 | 展示与处理 |
|---|---|
| 原状态为取消、受阻 | 优先保留真实业务决定；解除阻碍或恢复任务需 PM / agent 根据新事实更新原状态 |
| 原状态已确认完成且实际起止、完成依据齐全，起止有序 | 展示已确认完成；非空依据并不自动验证其内容真实性，原状态仍须来自有效验收决定 |
| 报已确认完成但事实不齐，或完成早于开始 | 展示待核对，请补事实或核对状态，不自动改日期 |
| 实际完成已录入，原状态尚未确认完成 | 起止有序时展示待确认；实际完成不等于验收通过 |
| 已填实际开始，未填实际完成 | 展示进行中；保留优先级更高的取消/受阻决定 |
| 负责人及当前预计起止齐全且有序 | 展示待开始；到了计划日也不会自动表示已经开始 |
| 其余 | 展示资料待完善；实际缺哪些资料仍由每日条件巡检指出 |

这是便于成员查看的执行状态，不是“全部资料就绪”判定。工作说明、完成标准、验收人、有效联系身份和本人反馈仍由 [每日巡检](每日任务巡检与资源影响.md) 检查。历史「阻塞说明」非空不能证明现在仍受阻，因此公式不靠这段文字推断。未来实际日期、资料可信度、父子完成冲突仍由巡检/校验核实；公式不是审计工具。

## 设置与日常维护

1. 在项目副本中核对「状态」「负责人」「当前预计开始」「当前预计完成」「实际开始」「实际完成」「完成依据」。当前 WBS 模型没有独立的「验收结果」列，不要直接引用不存在的字段。
2. 新建公式列并粘贴 Fx；用空任务、已排期、实际开始、实际完成待验收、确认完成、受阻、取消和起止倒置的样例逐项检查。
3. 在成员视图显示公式列及本人应填的事实字段，隐藏旧状态；PM 视图保留旧状态供核验和处理例外。隐藏不是删除，也不是权限隔离。
4. 原「状态」继续映射到适配器的 `work_status`。不要把输出文本或公式字段直接映射为原状态：例如「待核对」「资料待完善」不是原状态枚举，公式列也不可按普通字段写入。
5. agent 根据已核验的回复、完成证据和授权决定，通过既有读取→校验→回填→回读流程维护原状态；不能仅凭“收到”、日期到达或自动显示结果取消/关闭任务。

当前交付只提供公式和操作方案，真实租户尚未接入验证。保留 schema v7 和原状态选项，后续若要彻底迁移状态机，须同时处理历史数据、接入映射、校验和自动化。
