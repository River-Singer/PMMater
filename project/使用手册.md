# 使用手册

## 1. 选择数据入口

飞书首版以项目副本为事实来源，成员更新本人记录；通用智能体离线模式以最新 Excel 为入口，经本地校验提交到工作库再生成材料。两种模式共用字段和方法，不进行自动双主同步。

飞书内部智能体配置见 [接入说明](references/feishu-setup.md)。完整目录可作为通用智能体 Skill 安装，运行环境需 Python 3.11+、openpyxl 和 tzdata。`python -m pm_core.cli --help` 是实际命令参数的依据。

成员通过智能体对话或 Excel 提供与维护事实；智能体调用下列命令校验、回填和生成材料。HTML 是可直接打开的独立报告，不需要启动本地网页服务。

## 2. 本地初始化和导入导出

在本目录运行以下命令，工作文件放 workspace；实际项目日期与时区按配置填写：

```text
python -m pm_core.cli init --db workspace/project.sqlite3 --calendar-id CAL-PROJECT --start 2026-11-01 --end 2027-03-31 --timezone Asia/Shanghai
python -m pm_core.cli export --db workspace/project.sqlite3 --out workspace/当前项目.xlsx --calendar-id CAL-PROJECT
python -m pm_core.cli import-excel --db workspace/project.sqlite3 --file workspace/当前项目.xlsx --dry-run
python -m pm_core.cli import-excel --db workspace/project.sqlite3 --file workspace/当前项目.xlsx --actor project-member
python -m pm_core.cli check --db workspace/project.sqlite3
```

先填通讯录与项目概况，再填项目 WBS、独立运维事项和配套台账。保留原编号/版本；不能直接手改隐藏元数据、派生列或表头。新版本字段变化时从已迁移工作库重新导出，不将旧模板冒充当前格式。迁移会保存原库备份；不要删除备份直到核对历史关系与报表。v7 将历史非项目 WBS 复制到独立运维表并保留原编号，旧 WBS 兼容别名维持历史引用，不能作为第二份执行记录更新。旧工作簿指纹不匹配时重新导出，原文件不会被覆盖。新增非项目工作必须进入 operations；不要通过旧 WBS 接口继续混写。

初始自然日期表不代表节假日已全部核齐。项目和相关人员建立后执行：

```text
python -m pm_core.cli project-calendar --db workspace/project.sqlite3 --project-id <项目编号> --apply
python -m pm_core.cli attendance-plan --db workspace/project.sqlite3 --project-id <项目编号>
python -m pm_core.cli resource-review --db workspace/project.sqlite3 --project-id <项目编号>
```

项目-calendar 使用已确认提醒有效期/基线起止，内置已核验年度公告与确认公司例外；未覆盖年度保留待核验。项目结束变更后重新核对有效期，不能无限延伸。

## 3. 成员日常填写

[字段填写说明](docs/字段填写说明.md)提供条件清单。非员工每天确认地点、专职/兼项、可用时间与休假变化；全天入口展开 AM/PM，有数字的安排每半日分别填，不能重复全天总量。参见虚构输入 [daily-confirmation.json](references/examples/daily-confirmation.json)：

```text
python -m pm_core.cli attendance-confirm --db workspace/project.sqlite3 --project-id <项目编号> --person-id <人员编号> --date 2026-11-11 --file references/examples/daily-confirmation.json --actor <确认人> --apply
```

示例中的事实、日期和人员必须替换成真实确认值。未回复保持待确认，未来休假独立保存，预计可投入小时不自动变成实际人天。

周一填本周计划和可验证成果，计划会确认承诺；周五上午填实际结果、延期原因、影响和解决措施，会上审议决定。原基线、最新预测和本周承诺分别维护。

## 4. 汇报与会议回填

```text
python -m pm_core.cli project-report --db workspace/project.sqlite3 --out workspace/项目汇报.html --timezone Asia/Shanghai
python -m pm_core.cli weekly-report --db workspace/project.sqlite3 --out workspace/周报 --kind monday --confirm --actor <计划确认人> --timezone Asia/Shanghai
python -m pm_core.cli weekly-report --db workspace/project.sqlite3 --out workspace/周报 --kind friday --timezone Asia/Shanghai
python -m pm_core.cli management-review --db workspace/project.sqlite3 --period month --out workspace/月度复核.json --html workspace/月度复核.html --lookahead-weeks 6
```

`--confirm` 只在实际计划会确认后使用，不能预先确认或倒签。周五会后新版本用 `--review-of <会前报告编号>` 关联已保存会前报告，保留当时事实。截止以后才完成的工作进入新版本，不覆盖历史。

妙记先读取/提取为有来源的动作，规则见 [会议行动契约](references/meeting-actions.md)。示例仅展示格式，不可直接作用于正式项目：

```text
python -m pm_core.cli actions-run --config workspace/project-config.json --db workspace/project.sqlite3 --ledger workspace/runtime.sqlite3 --file workspace/actions.json
```

预览通过并已有执行授权时加 --apply。普通范围内动作无需逐条请示；删除、验收、基线/范围和重要资源调整保留具名决定依据。含糊对象、建议、冲突进入待处理。真实删除检查引用；取消工作改状态。

## 5. 持续跟进与飞书

[飞书接入](references/feishu-setup.md)说明原生宿主工具和可选桥接。桥接先生成并填全配置，令牌来自宿主环境：

```text
python -m pm_core.cli feishu-config-template --out workspace/feishu.json
python -m pm_core.cli feishu-report --config workspace/feishu.json --out workspace/审议材料.html
python -m pm_core.cli report-publish --config workspace/feishu.json --ledger workspace/runtime.sqlite3 --file workspace/审议材料.json
python -m pm_core.cli agent-tick --config workspace/feishu.json --ledger workspace/runtime.sqlite3
```

报告 HTML 和旁边 JSON 共享同一读取快照。文档发布/提醒默认预览，已配置并授权后启用 enabled 并加 --apply。宿主需持久调度 tick、保存台账并处理失败；不运行宿主就不会自动提醒。原有 weekly-tick/archive-tick 只做本地周报/留档，不等于飞书催办。

已知失败默认总计最多尝试 3 次（首次 + 2 次重试）；未知发送/写入结果不自动重试。核验远端结果后，使用 runtime-reconcile 与 `{key,outcome:applied或not_applied,evidence}` 恢复台账；必须有真实查询依据，不能为了重发而伪造“未执行”。确认未执行后才允许恢复失败动作，日程已创建的步骤保留。

## 6. 查看和验证

直接双击生成的 `workspace/项目汇报.html` 或包内 [本周项目汇报](demo/本周项目汇报.html) 查看。页签、WBS 层级展开、工作周与日视图切换均在文件内完成。修改数据后重新生成一份带实际截止时点的报告。

需要生成虚构材料或验证安装时运行：

```text
python -m pm_core.cli demo --out workspace/虚构演示
python -m unittest discover -s tests -q
```

Windows 也可运行 `run_demo.bat`，它在 `demo_run/` 生成离线示例，不启动网页服务。

Excel/HTML 输出是生成时点快照；跨系统写入成功、邀请受理和成员实际接受分别核验。没有现场租户测试时不声称已经上线。`install_weekly_task.ps1` 仍可用于注册本地周报定时任务，它调用生成命令，不运行网页服务；飞书提醒由已配置的智能体宿主负责。
