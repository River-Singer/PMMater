# 日、周、月与项目阶段

## 成员更新入口

项目 WBS 与运维/优化事项分别维护。一个事项只设一个执行负责人，其他参与者/协调人用关联表达；不把两张表同时维护成同一执行记录。按变化展开必填字段，日常视图保留标题、状态、责任、预计日期、进展和下一步。

| 时点 | 成员维护 | PM / agent 跟进 |
|---|---|---|
| 每个项目工作日上午 | 非员工确认驻场/远程、专职/兼项、半日可用安排与未来休假变化 | 真实 @、未确认清单、资源冲突；已确认休假按项目政策免普通重复催签 |
| 每个项目工作日10:00 | 所有任务负责人补计划、明细、完成标准及本人反馈；协调人补资源落实依据 | 叶子任务就绪 → 父级影响 → 项目节点；人力、接口、决策、物资缺口统一进延期风险材料 |
| 每个项目工作日17:00 | 回答当天适用的问题，补真实起止/剩余工作、风险原因、继续或等待条件及补救安排 | 重读数据与真实回复，向已配置负责人汇总未闭环事项、延期/资源风险和需要的支持；失败发送与未回复分开 |
| 周一上午 | 全体任务负责人更新本周工作、计划/预计开始完成、可验证中间成果、期限与验证方式；非员工另确认净容量和项目/运维分配 | 检查依赖、缺字段、资源冲突和待决定项 |
| 周一计划会 | 确认本周承诺与责任 | 按真实确认时间保存承诺快照，跨周任务保留整体预计日期 |
| 周中变化时 | 实际开始、成果、阻塞、预测变化、所需协助、下一检查点 | 到期/延期/陈旧资料/验收/风险复核等按条件催办 |
| 周五上午 | 实际结果、完成依据、未完成原因、延期说明、影响与补救措施 | 已完成、待验收、逾期和尚未到期分开；周五下午到期不能提前记失约 |
| 周五总结会 | 审议补救方案、作决定、分配下一步 | HTML 列原因、影响、措施、负责人、期限、待决定项；会后回填并保留新版本 |
| 月度复核 | 复用现有事实，补充未来关键窗口 | 看里程碑预测、范围变更、风险和未来 4–6 周人员需求，不另造一套重复月报 |
| 阶段检查 | 交付证据、验收/移交条件、未关闭风险 | 检查齐备/缺失；阶段通过由有权人员决定，不因日期到达自动放行 |

周会遇假日需真实会议实例或确认的替代日期；不能倒签周计划。月末材料注明统计期间与数据截止，跨月周报不直接相加。没有历史快照不编造预测变化。

## 提醒与风险

提醒包含记录、触发原因、具体待填字段、负责对象、截止和停止条件。执行脚本只检查事实与配置阈值，不猜概率或关键路径。以下语义独立：未来风险、已经发生的问题、阻塞、实际延期、预测延期、待验收、信息缺失/过期。

每日任务就绪与资源影响巡检使用 `workflow_time="10:00"`，问题回复截止 `response_cutoff="17:00"`，汇总时点 `escalation_time="17:00"`（用户指定，按项目时区和已核验工作日）。其他示例时刻仍为 09:00 开始收集、10:30 截止、10:30/16:00 异常巡检、18:00 后静默，可按项目调整。宿主须在10点和17点唤醒，tick 不在后台自行调度；未到时不发本轮消息，延迟唤醒可在当天补执行。已解除问题从下一轮剔除，已回复但风险未解除仍跟进。同日同类事项防重，未知发送结果先核验，兼容按人合并。

任务资料就绪、本人反馈和资源落实按 [每日任务巡检与资源影响](../docs/每日任务巡检与资源影响.md) 执行。未排期待分流任务不能漏检，也不能从总体分母移除。图中父子关系、显式前后置依赖和资源来源分开，未关联资源列待定位；未登记需求不视为资源已落实。所有未落实资源进入潜在延期风险，已经发生延期仍独立审议。

日常群跟进按人合并、逐项真实 @ 并列“类型、动作、DDL、完成/回填依据、来源、短影响”。决策找记录中的明确决定人，执行找负责人；责任或身份不清由有效 PM 协调。人力事实影响由 PM 协调，员工仍只豁免例行人力确认。没有行动期限写“待确认”，不拿任务预测日或接口预计就绪日代替。完整证据放入汇报文档及 HTML 折叠详情，不直接把长篇风险分析当群催办消息。

已确认数据仍缺实质进展时只报告“资料需更新”，不推断成员未工作。高风险结论必须有影响/概率尺度或明确事件依据；P0、延期天数与风险等级不能互相替代。

实际起止、缺估算、等待恢复和补救问题按 [每日字段情景与17点升级](../docs/每日字段情景与17点升级.md) 执行。回复截止独立于行动DDL；下午须有成功发送与完整消息覆盖才可说未观察到回复，收到/部分回答、无法核验、未发送分别列明。字段补齐可解除资料缺口，但不是群回复证据。任务「状态」可另建只读 [公式展示](../docs/状态自动显示与维护.md)，无需让成员天天手选待分流；原状态与真实业务决定保留。

## 日历、签到和容量

项目日历按已确认提醒有效期（未单设时使用基线起止）覆盖全部自然日期。年度官方假期/调休来源与完整性独立保存，再叠加已确认公司例外；成员级公司例外与个人休假只影响本人。2026/2027 内置数据可用，更远年份保持待核验直到官方来源落实。日期存在不代表该年度已核齐。

非员工身份与项目角色分别维护；成员参与窗口、真实飞书身份缺失时先提示缺口。签到是安排确认，不是人事考勤。未回复为待确认；上午不能把下午计划记录成实际。全天输入展开 AM/PM，具体小时按半日填写，禁止复制全天总量两次。

人力资源确认按通讯录的**成员类型**筛选，不按项目角色：`vendor`（供应商）、`external`（其他非员工）进入确认范围；`employee`（员工）不参加每日安排、周容量和月度未来资源窗口的确认或缺失催填。未知/缺失类型先交 PM 核实，不当作非员工发送确认。员工已有容量、休假和安排记录仍保留、可查可更正；未确认的历史数据仍为未确认事实，不能因免确认自动标成已确认。月度材料不为员工逐周补出“缺失容量待确认”，仍显示已经登记的资源和休假影响。

“确认当天安排”及 `attendance-confirm` 不给员工或未知类型新建确认记录；已有记录可以单独更正。周资源表和休假表保留一般事实维护入口，PM 可继续维护员工已有或新的真实安排。员工承担的任务更新、延期、风险、会议行动和验收提醒不受此筛选影响。当前脚本没有独立的周容量自动催办任务；宿主配置这类任务时也须采用相同成员类型筛选。

每人每周：净可用 C 包含“项目 + 对应运维”；项目安排 P、运维安排 O、未分配缓冲 B 分开，可再安排量 C−P−O−B。请假/其他项目占用已从 C 扣除则不再扣；插单消耗缓冲后把 B 转到相应分配。值未知就保留未知，不能从驻场、任务数或工期推算工时/个人效率。

项目结束或成员到期但仍有工作时提示 PM 核实窗口与交接；不能把停签当成已经退场。项目正式结项后停止原项目提醒，遗留运维按接管安排承接。

## 方法依据

采用 [PM² 生命周期与治理](https://pm2.europa.eu/pm2-methodologies/pm2-project-management_en)、[GovS 002](https://projectdelivery.gov.uk/library-products/government-functional-standard-govs-002-project-delivery/)、[APM 资源规划](https://www.apm.org.uk/resources/find-a-resource/competence-framework/overview/planning-managing-deployment/)及 [Kanban Guide](https://kanbanguides.org/the-kanban-guide/2025.5/) 的可裁剪原则。具体提醒时刻和阈值是本项目配置，不是这些方法规定的通用 SLA。
