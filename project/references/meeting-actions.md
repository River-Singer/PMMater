# 妙记 → 可追溯行动 → 回填

## 提取

先核对具体会议实例、项目与妙记链接。读取元信息、摘要/待办和必要逐字稿；AI 待办名字不等于已核实人员 ID。未就绪稍后重查；无权限、读取截断或缺源要明确报告，不当成会议没有行动。

将每项话语分类为事实、明确决定、建议、待讨论或冲突。保留原句、来源 URL、可定位片段/时间和读取版本；没有时间戳就不要编造。只凭“可以考虑”不能改日期，“下周找时间”不能创建确定日程，“已经上线”不能自动当验收通过。

先查询既有记录与远端映射，同名人/任务必须消歧；新增事项按项目交付或独立运维分流。通讯录用邮箱或姓名+部门查找候选，再核实唯一记录；姓名、部门和邮箱都不能代替已确认的稳定记录身份。首次抽取为行动分配稳定 ID，后续妙记修订复用 ID；不要按段落序号或全文哈希重新创建。

新版母版的 WBS/项目编号由公式展示，可能随「所属项目」或「英文缩写」变化。先从已读取记录解析稳定身份，再生成行动；不能把公式值变化当作任务删除后重建。父子层级依赖「父级WBS／抽屉」关联，不从编号字符串推断。涉及母版结构时先读 [母版变更同步记录](../docs/飞书母版变更同步记录.md)。

## 可执行行动 JSON

示例在 examples/meeting-actions.json，均为虚构，不是本项目指令。顶层 `{actions:[...]}`，每条：

- id：稳定行动身份；source：id/url/quote/kind。kind 只在有证据时选 confirmed_fact/confirmed_decision，其余保留待确认。
- operation：query/create/update/delete/book/reschedule。
- 业务表动作：table、record_id（当前后端映射后的精确稳定 ID）、values（只写涉及字段）、expected（提取时原值）。离线 Excel 使用本地记录编号；飞书使用接入配置定义的稳定身份，不能直接填姓名或可变的公式展示编号。每个修改字段都要原值；删除需要完整原记录。
- 重要变更：approval.by 属于配置 decision_makers，approval.evidence 指向实际决定；普通明确动作按配置授权自动执行。
- 删除：delete_intent=true 表示明确删除数据；检查所有引用并留删除前快照。“取消/暂缓执行”应改业务状态，不是 delete。
- 预约：calendar_id、values.title/start/end/organizer_id/attendees；时间须带时区，organizer_id 对应已配置调用身份。改期另带 event_id 与 expected_event 原字段。缺时段/名单只留待补行动。

飞书表配置 `identity:"record_id"` 时，create 可省略 `record_id`，且不在 `values` 中提供 `id`；成功后从 `detail.record_id` 取得远端身份，再编排依赖它的后续行动。稳定行动 `id` 与来源 `source.id` 用于防重，不能把它们伪装成平台记录 ID。默认业务编号模式与离线模式仍使用原有编号规则。配置与迁移边界见 [飞书接入](feishu-setup.md)。

提取后的 JSON 是交给确定性执行器的业务输入，不能夹入任意脚本或绕过配置权限。

## 执行与恢复

本包 `actions-run` 默认校验预览，加 `--apply` 才按 enabled 配置执行。Excel 模式使用 --db 和本地 Store；飞书模式使用映射好的 Base。按条汇报 preview/pending/conflict/succeeded/failed/unknown/revision_pending。

- 写前读最新值；与 expected 不同则冲突，不覆盖新人工事实。真实飞书缺少本包可证明的原子版本锁，预读仍有竞态，接入应按表串行并回读。
- 新增 WBS 只提交可写业务事实与真实关联，等平台生成编号后回读；不写「WBS编号」、项目公式「编号」、「流水号」或「创建时间」。公式取值为空/异常要报告，不能用模型猜出的编号补写。创建回读结果应同时保留稳定记录身份与当前展示编号。
- 使用桥接的 `display_field` 时，写后展示值保存在 `detail.display_value`；空值标为 `unknown`，`detail.record_id` 仍保存已创建的记录。核对公式和原记录后恢复，不能再次创建替代记录。
- 成功动作再次处理直接复用；同一行动内容改变时标 revision_pending。对照当前值生成明确的纠正行动，保留前项来源，不能偷偷重放新增。
- 远端超时、进程在发送中断或回读不一致标未知；人工/宿主先查询远端结果，不能换台账、换行动 ID 后盲重试。执行台账的 running 也按未确定结果处理。
- 日程创建后保存 event_id，再邀请；已知邀请失败重试邀请，不建第二个日程。发送/邀请成功不代表成员已读或接受。
- 多条行动独立完成，不用一项含糊阻塞整场会议已明确的普通行动。保留来源、修改前后值、执行身份/时间和实际结果。

## 周五审议材料

项目和运维分别列：对照日期、实际/预测偏差、延期原因、影响、解决措施、行动负责人/期限、候选方案、决定人/期限及缺资料。会前版保留待审议状态；会后版关联原报告，展示实际决定、更新预测和回填结果。补救行动完成不等于原任务完成，更不能擦掉原延期。

填写样例见 [样例导航](examples/README.md)：候选周成果、周五具名决定、确认时间与名单的预约。验收 accepted/rejected、验收时间及登记的正式决定都要求有权人的依据；提交 pending 与普通实际日期事实按配置范围处理。

纪要涉及日期纠错/重排时，使用 [日期变更审议政策](../docs/日期变更审议与留痕.md)记录精确修改范围及事前批准或事后复核。后者不能描述为提前批准。
