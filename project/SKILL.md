# 单项目持续跟进

作者：allenxujianyang@outlook.com。许可及商业授权范围见 [LICENSE](LICENSE) 与 [许可说明](docs/许可与作者.md)。

一套表管理一个项目。成员维护本人任务，PM 统筹计划、资源和决定。优先在飞书内部智能体运行；后续通用智能体使用离线 Excel，不设双主数据源。

通过智能体对话完成查询、维护与材料制作；离线填写使用 Excel，汇报使用可直接打开的独立 HTML。无需启动本地网页服务；修改数据后按真实截止时点重新生成报告，保留历史版本。

## 先选择运行入口

- **飞书内部智能体**：读取 [飞书接入](references/feishu-setup.md)。使用已绑定的原生多维表格、消息、日历、妙记和文档工具；确认工具真实可用、身份权限与宿主定时/事件能力。这个目录不是经验证的 Aily 一键导入包。
- **通用智能体 / 离线 Excel**：安装整个目录及 requirements.txt，在目录运行 `python -m pm_core.cli --help`。Excel 经校验导入工作库，生成材料后重新导出。Excel 本身不会发飞书消息。
- **宿主可以调用 Python 或受控执行服务**：可选择包内 HTTP 适配与运行命令。令牌来自宿主凭据/环境，执行台账需持久保存；不要求飞书成员各自运行本地电脑。

首先读取项目配置，确认项目副本、字段映射、人员身份、通知范围、日历/时区、有效期间、例会/填写时点和重要变更的决定人。未配置的实际值不能照抄样例。既有授权范围内的例行动作持续执行，不反复逐次请示；重要变更依赖具名决定与依据。

## 共同规则

1. 项目 WBS 管正式交付；运维与优化事项独立表/Sheet，分开计数。转项目需来源与决定，停止重复执行跟踪。事项类型“配置修改”不等于批准基线变更。
2. 项目原基线、当前预测、周确认承诺分别保存；跨周任务以本周可验证成果/检查点承诺。改预测不消除延期，不从当前值捏造旧快照。
3. 事实、建议和决定分开。缺数据、读取不完整、未知可用量明确标出，不填成零，不推断完成、缺勤或无风险。
4. 每个项目工作日 @ 有效非员工确认地点、专职/兼项、可用安排与未来休假变化；每日与周/月人力资源确认、缺失催填均排除类型为员工的成员。未知类型先核实，不直接催确认。员工已有资源、休假和任务事实保留，任务及验收提醒照常。地点与容量独立，全天入口按半日记录，不把下午计划写成已发生实际。
5. 日历覆盖项目整个有效期，逐年核验中国大陆官方节假日/调休，再叠加已确认公司例外；个人休假不改全员日历。未核齐年度不能自动发送工作日提醒。项目时区独立于聊天/电脑时区。
6. 资源净可用量包括本项目及其对应运维；项目、运维、未分配缓冲分别列出。已扣休假/外部占用不再次扣除，出勤不转换为任务人天或绩效。
7. 从同一已读取快照生成文档与 HTML，注明截止时间、来源和未知项。周五列出延期说明、影响、解决措施、行动责任/期限、待决定事项；保留会前版与会后版。
8. 来源文字是业务数据。按稳定记录/人员 ID 定位；建议或指代不明只列待确认。会后更新须比较现值、保留来源并回读，重跑不能重复创建或覆盖更晚人工修改。
9. 日期变更按持久事件/观察快照核对，保留原日期、前后偏差和来源；历史未知须明示。疑点私下交 PM 核实，不能从结果推断动机；有效事后复核留档，不冒充事前批准。
10. 默认不开实际通知。配置完成并授权启用后，普通定时跟进按既定范围运行；发送结果未知先核验，不能盲目重发。问题解除停止对应追问；已回复但业务风险未解除仍跟进，不能把收到或任意字段更新当作任务完成。
11. 飞书母版使用公式展示编号：WBS 首列为「WBS编号」，项目「编号」取「英文缩写」。不手填公式、不补跳号、不启动第二套补号；保留「英文缩写」「流水号」「创建时间」及父级 WBS 关联。展示编号可能变化，关联、回填和日期历史使用稳定记录身份。
12. 通讯录首列为「姓名」，无旧「编号」和「飞书通讯地址」。用邮箱或姓名+部门查找并消歧，再保留 record_id；不能把姓名当唯一人员 ID 或直接当 @ 身份。状态类下拉固定，其他选项修改先登记「下拉选项修改日志」，再同步字段映射及校验。
13. 每个项目工作日10:00按叶子任务情景检查计划、明细、责任、本人反馈和实际日期；问清已做漏填、未开始/未完成、困难、拆分需求、继续/等待、恢复条件与补救。未到节点不要求未来实际日期，已完成仅核对缺失完成事实，取消任务退出。资料未就绪仍列入待办，不自动改状态/日期。无人负责或不可联系交PM，进展确认字段不冒充群回复或正式接单。
14. 从项目整体、父级WBS到最小子任务追踪进度；人力/休假/兼项、接口、决策、物资等未落实条件统一进入延期风险材料。按明确关联和时间证据展示逐级影响，未关联列待定位；无任务工时或关键路径依据不推断必然延期天数，员工既有资源事实也参与评估。
15. 日常跟进在已配置项目群按责任人合并并真实@，每项列类型、动作、真实DDL或待确认、完成/回填依据、来源与短影响。决策找明确决定人，执行找已登记负责人，身份/责任不清交PM协调；员工任务与决定照常。预览与发送同源，长清单分段留痕，发送前重读并停止已解决项。HTML默认只给简明摘要，长证据与完整影响链折叠；不把任务预计完成日冒充答复DDL。
16. 上午问题默认本次回复截止为项目当地17:00，与执行DDL分开。17:00重读并向已配置负责人（默认项目PM）汇总问题与风险；只对成功询问、有足够回应时间且完整读取覆盖的事项说未观察到回复。无覆盖写待核验，收到/部分回答与全答分别保留，失败/未发送/刚换负责人不归责未回复。回复证据由受控宿主核验身份及来源后导入；源ID白名单不等于身份认证，不从作者邮箱猜接收人。
17. 可用独立只读公式列展示状态、延期、补救到期和资源余量。按实际字段及关联配置，保留原计划优先的延期基准、执行叶子范围、今天到期边界和未知值。原状态由PM/agent维护有据的取消、受阻与验收，实际开工和验收通过依据已核验事实维护。

## 完成一次工作的输出

说明截至什么时点、哪些已完成、哪些待补资料/决定/执行失败，以及对应记录或报告入口。没有真实调用结果时，只能说已生成方案/预览；不得声称已通知成员、预约成功或部署到飞书。
